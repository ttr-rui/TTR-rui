## 二、测试设计方法

采用三类白盒设计方法组合，目标是让每个函数的**正常分支与异常分支**都被执行到：

| 方法 | 用法 | 举例 |
| --- | --- | --- |
| **等价类划分** | 把输入划成若干等价集合，每类取一个代表 | 文件编码分为 UTF-8 / GBK / 非法字节三类；参数个数分为 3 个（合法）与 0、2、4 个（非法） |
| **边界值分析** | 取区间的端点与临界点 | 相似度取 0.0 与 1.0；参数个数取 3 的左右邻居；空文件、纯空白文件、纯标点文本 |
| **异常路径覆盖** | 主动构造触发 `raise` 的输入 | 文件不存在、路径指向目录、目标目录不可写、编码全部失败 |

测试数据全部由 `tempfile.TemporaryDirectory()` 在临时目录中动态生成，不依赖磁盘上的任何固定文件，因此**能在任何机器上直接运行**，也不会污染被测目录。

## 四、典型用例代码

### 4.1 构造编码异常：验证兜底解码

思路：直接写入原始字节 `b"hello\x80world"`。0x80 在 UTF-8、GBK、
GB18030 三种编码中都不是合法起始字节，必然触发三级回退，
从而覆盖「忽略非法字符强制解码」这条分支。

```python
    def test_09_invalid_bytes_fallback(self):
        """异常路径：三种编码均失败时，忽略非法字符兜底解码。"""
        path = self.make_bytes("bad.txt", b"hello\x80world")
        self.assertEqual(read_text(path), "helloworld")
```

### 4.2 构造除零风险：验证模长为 0 的短路返回

思路：词频字典非空（能通过 `if not freq_a` 检查），但所有计数为 0，
使得模长 `sqrt(0) = 0`。若没有短路保护，这里会抛 `ZeroDivisionError`。

```python
    def test_37_zero_vector_is_zero(self):
        """覆盖率补测：向量模长为 0 时直接返回 0，不触发除零。"""
        self.assertEqual(cosine_similarity({"词": 0}, {"词": 1}), 0.0)
```

### 4.3 构造端到端场景：验证入口退出码与文件内容

思路：用 `mock.patch.object` 替换 `sys.argv` 模拟命令行调用，
用 `redirect_stdout` 吸收程序输出，避免污染测试报告；
断言退出码与答案文件的**实际文本**（而不是浮点值），
这样才能同时验证「保留两位小数」这一格式要求。

```python
    def _run(self, argv):
        """在静默标准输出的情况下调用 main()，返回退出码。"""
        with mock.patch.object(sys, "argv", argv):
            with redirect_stdout(io.StringIO()):
                return main.main()

    def test_32_success_returns_zero(self):
        """正常路径：退出码 0，答案文件内容为题面样例的重复率。"""
        original = self.make_file("orig.txt", SAMPLE_ORIGINAL)
        copied = self.make_file("copy.txt", SAMPLE_COPIED)
        answer = os.path.join(self.dir, "ans.txt")
        code = self._run(["main.py", original, copied, answer])
        self.assertEqual(code, 0)
        with open(answer, encoding="utf-8") as handle:
            self.assertEqual(handle.read(), SAMPLE_SIMILARITY)
```

### 4.4 全路径覆盖：验证脚本运行入口

思路：用 `runpy.run_path(..., run_name="__main__")` 把 `main.py`
当作脚本执行一次，使 `if __name__ == "__main__": sys.exit(main())`
这一行也被覆盖——这是 `import main` 方式永远走不到的分支。

```python
    def test_38_script_exit_code(self):
        """覆盖率补测：以脚本方式运行时经 sys.exit 返回退出码 0。"""
        original = self.make_file("orig.txt", SAMPLE_ORIGINAL)
        copied = self.make_file("copy.txt", SAMPLE_COPIED)
        answer = os.path.join(self.dir, "ans.txt")
        argv = ["main.py", original, copied, answer]
        with mock.patch.object(sys, "argv", argv):
            with redirect_stdout(io.StringIO()):
                with self.assertRaises(SystemExit) as raised:
                    runpy.run_path(MAIN_SCRIPT, run_name="__main__")
        self.assertEqual(raised.exception.code, 0)
```

### 4.5 构造乱序场景：验证特征携带字序信息

思路：取一段语义完整的短句，把**每一对相邻的字互换**构造出「乱序版」。
若特征不含字序信息（例如把文本切成单个字后做词袋），这两个字序不同的
串会被判为完全重复；2-gram 特征则因相邻关系被打乱而大量失配。

```python
    def test_42_word_order_affects_similarity(self):
        """顺序敏感：把相邻两字互换后，相似度必须明显低于 1。"""
        freq_a = build_word_freq(tokenize("天气晴朗我去看电影"))
        freq_b = build_word_freq(tokenize("气天朗晴我去看影电"))
        value = cosine_similarity(freq_a, freq_b)
        self.assertLess(value, 1.0)
        self.assertGreater(value, 0.0)
```

两串各切出 8 个 2-gram 特征，共有 `我去`、`去看` 两个，余弦为
`2 / (√8 × √8) = 0.25`。若把特征粒度退回「单字袋」，这两个串的字频
完全相同，相似度会变成 `1.00` —— 该用例因此成为防止算法退化的护栏。

## 五、测试评价

### 5.1 这组用例够用吗

**结论：够用，并且做到了语句级全覆盖。**

- 42 个用例覆盖了 6 个模块的全部可执行语句，语句覆盖率 100%，无 Missing 行。
- 关键风险点全部被主动验证：除零、空输入、非法编码、参数个数错误、
  路径不可写、退出码语义。这些正是评测中会导致「异常退出扣 2 分」的场景。
- 断言层面不仅检查「不抛异常」，还检查返回值、退出码和**文件实际文本**，
  因此「保留两位小数」这类格式要求也在测试保护范围内。

### 5.2 算法升级后补充的定向用例

交付前的验算发现了一个**算法层面的缺陷**：原「jieba 分词 + 词袋」方案
对**词序完全不敏感**。用老师下发的 `orig_0.8_dis_*.txt`（把相邻两字互换）
与原文本对比时，算出的重复率高达 `0.98 ~ 1.00`，与肉眼判断明显不符 ——
因为词袋模型只统计每个词出现几次，字序变了它察觉不到。

把特征粒度改为「汉字 2-gram」（相邻两字构成一个特征）后，特征本身
携带了局部顺序信息，乱序会破坏大量特征，相似度随之下降。为把这个
性质固定住，新增 3 个用例：

| 编号 | 用例 | 锁定的性质 |
| --- | --- | --- |
| 40 | `test_40_tokenize_slices_ngram_features` | 特征粒度必须是相邻两字；标点剔除后两侧字符要拼接 |
| 41 | `test_41_short_text_has_no_feature` | 有效字符不足 2 个时不产出特征（空文本、纯标点） |
| 42 | `test_42_word_order_affects_similarity` | **顺序敏感**：相邻两字互换后相似度必须低于 1 |

其中用例 42 是防止算法退化的护栏：若日后有人把特征粒度改成不含字序
信息的「单字袋」，该用例会立刻失败。

### 5.3 算法升级前后的实测对比

用老师下发的测试文本实测（原文 `orig.txt` 分别与 5 个抄袭版对比）：

| 抄袭版 | 生成方式 | 原「整词词袋」 | 现「汉字 2-gram」 |
| --- | --- | --- | --- |
| `orig_0.8_add.txt` | 随机插入无关汉字 | 0.99 | **0.90** |
| `orig_0.8_del.txt` | 随机删除汉字 | 0.99 | **0.90** |
| `orig_0.8_dis_1.txt` | 相邻两字互换 | 1.00 | **0.97** |
| `orig_0.8_dis_10.txt` | 相邻两字互换 | 0.99 | **0.91** |
| `orig_0.8_dis_15.txt` | 相邻两字互换 | 0.98 | **0.75** |

改动前，改动程度差异很大的 5 个抄袭版全部挤在 `0.98 ~ 1.00` 的窄区间内，
几乎无法区分；改动后拉开到 `0.75 ~ 0.97`，且**改动越多、相似度越低**，
与肉眼判断一致。题目给出的 22 字样例在两种算法下均为 `0.61`。

### 5.4 已知局限

- 用例 36 通过 `unittest.mock` 注入 `PermissionError` 来模拟打开失败，
  属于桩测试；真实的权限异常在测试环境中难以稳定复现，这是合理的取舍。
- 测试未覆盖超大文本（数百 MB）的性能表现，该部分由性能分析一节
  （375 KB 长文本基准）单独负责。
